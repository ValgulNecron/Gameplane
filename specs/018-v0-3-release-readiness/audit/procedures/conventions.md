# Procedures: shared conventions

## Conventions (shared by every procedures file)

- **Cluster**: `export KUBECONFIG=~/kubelab.yaml`. Release `gameplane` in `gameplane-system`; games namespace `gameplane-games`.
- **Chart source for live Helm toggles (FR-018)**: once an RC is deployed, every live `helm upgrade gameplane charts/gameplane …` in these procedures runs against the chart that is actually deployed, not this checkout's `charts/gameplane`. The git tree's `Chart.yaml` stays at `version`/`appVersion` `0.2.0-beta.8`; only the packaged chart gets the RC version, stamped by the `chart version` step of `.github/workflows/release.yaml`. Upgrading with the local chart would swap the RC's templates for the tree's and, while `image.tag` is empty, pull the tree's `appVersion` images instead of the RC's (`gameplane.imageTag`, `charts/gameplane/templates/_helpers.tpl`). Pull the deployed RC chart once per round, off-git: `rm -rf ~/gameplane-audit-018/rc-chart && helm pull oci://ghcr.io/valgulnecron/charts/gameplane --version 0.3.0-rc.N --untar -d ~/gameplane-audit-018/rc-chart`. Then read `charts/gameplane` in those commands as `~/gameplane-audit-018/rc-chart/gameplane`. After each toggle, `helm list -n gameplane-system` must still show chart `gameplane-0.3.0-rc.N`. `helm template charts/gameplane` rendering checks are unaffected.
- **Reaching the API** (OD-016): the ingress host `gameplane.local` does not resolve from the audit devbox, so run `kubectl port-forward -n gameplane-system svc/gameplane-web 18080:80` and use `GP=http://127.0.0.1:18080`. The ingress sends `/` to `gameplane-web`, which serves the dashboard and proxies API paths to `gameplane-api`.
- **Sessions**: `POST $GP/auth/login` with `Content-Type: application/json` and body `{"username":"…","password":"…"}`. The response sets `gameplane_session` (HttpOnly) and `gameplane_csrf` cookies. Both are `Secure`, so curl drops them over plain HTTP. Capture them from the response headers (`curl -D`) into `~/gameplane-audit-018/session-<role>.txt` (off-git, mode 600). Send them back as `-H "Cookie: gameplane_session=…; gameplane_csrf=…"`. Every mutating request also sends `-H "X-Gameplane-CSRF: <gameplane_csrf value>"`.
- **Accounts**: one session per role per round: `audit018-admin`, `audit018-operator`, `audit018-viewer`, and `audit018-collab` where a collaborator is needed. Admin access follows OD-015: generate a password, save it to `~/gameplane-audit-018/admin.env` (mode 600, off-git), then feed it over stdin — the image's entrypoint is `/api` and has no shell, so a shell env-var trick doesn't reach it: `PW=$(openssl rand -base64 24) && echo "GAMEPLANE_ADMIN_PASSWORD=$PW" > ~/gameplane-audit-018/admin.env && chmod 600 ~/gameplane-audit-018/admin.env && echo "$PW" | kubectl exec -i -n gameplane-system deploy/gameplane-api -- /api bootstrap-admin --username audit018-admin --password-stdin` (`--password` and `GAMEPLANE_ADMIN_PASSWORD` also exist per `api/cmd/bootstrap.go`, but both leave the password in a shell arg or env dump; `--password-stdin` avoids that, matching `procedures/upgrade.md`'s baseline-beta8 step 1 and the command actually logged in `rounds.md`).
- **Collaborator account (OD-021 item 15)**: `POST $GP/users/` always sets the new user's primary role via a cluster-wide binding (`api/internal/handlers/users.go`), so a "collaborator only" account first needs a role with no permissions. Round setup: `POST $GP/roles/` creates `audit018-norole` with `"permissions": []`; `POST $GP/users/` creates `audit018-collab` with `"role": "audit018-norole"`; `PUT $GP/servers/<audit018-server>:collaborators` (route mounted at `api/internal/handlers/ownership.go:142`, handler at `:210`) adds `audit018-collab`'s user id to one `audit018-` GameServer's collaborator list. Credentials go in `~/gameplane-audit-018/collab.env` (mode 600, off-git). Round teardown removes, in order: the collaborator grant (`PUT …:collaborators` with the id removed), the `audit018-collab` user (`DELETE $GP/users/{id}`), the `audit018-norole` role (`DELETE $GP/roles/audit018-norole`), and `~/gameplane-audit-018/collab.env`.
- **Login budget**: IP burst 10 (5/min), user burst 6 (3/min). Each procedure states its login cost. Procedures that spend the budget on purpose (brute force, throttling) are marked **deferred to T031** and run last.
- **Naming and isolation**: every created object is named `audit018-<purpose>[-n]`, 63 characters at most. Objects created with `kubectl` also get the label `gameplane.io/audit: "018"`. Pre-existing objects are never written to. That covers GameServers `mc-fabric`, `soak-bogus-pool`, `soak-no-preference`, `soak-pool-west` and `squad`, and ModuleSources `default` and `uploads`. A procedure that needs an existing object creates its own `audit018-` copy first.
- **Evidence**: saved under `audit/evidence/<INV-ID>/`, redacted. A share token is written as `<token>`, and no cookie, CSRF value, password or secret is ever written. Each file stays under 1 MB.
- **Automatable?**: say `yes` or `no`. For `yes`, propose a bucket from `test/e2e/buckets.sh`: operator, api-auth, api-roles, api-rbac, api-agent, api-mods, ratelimit, bot-fast, bot-heavy, multicluster, upgrade, or `web-api` (new, OD-021 item 12; not yet in `test/e2e/buckets.sh`) for `web.md` procedures that previously proposed the nonexistent `api` bucket.

### Per-round setup and teardown (OD-021)

Beyond the accounts above, some rows need cluster-level fixtures that exist only for the round they're used in. Create these at round setup and remove them at round teardown; record what was created/removed in `rounds.md` under that round's **Cleanup** field (or a dedicated subsection if the list is long).

- **Restic backend (items 9, 16)**: derive a Deployment + Service named `audit018-restic` from `test/e2e/fixtures/restic-server.yaml` (same image, args and `emptyDir`; rename `gameplane-test-restic` to `audit018-restic` throughout and add the label `gameplane.io/audit: "018"` — do not apply the fixture as-is, since its unmodified name and missing label would violate the naming/isolation rule above and risk colliding with a copy of the e2e fixture already on kubelab), then create an `audit018-restic` Secret (the restic repository password/URL, following `test/e2e/fixtures/backup-restic-secret.yaml`'s shape but with `repo: "rest:http://audit018-restic.gameplane-system.svc:8000/"`) in `gameplane-games`, labeled `gameplane.io/audit: "018"`. The chart ships `networkPolicies.enabled: true` (`charts/gameplane/values.yaml:328`) with `default-deny-egress` in `gameplane-games` opening only DNS, so backup Job pods cannot otherwise reach `audit018-restic.gameplane-system.svc:8000`; the fixture's third object, `allow-egress-to-restic`, cannot be reused as-is because it selects `app.kubernetes.io/name: gameplane-test-restic`, a label the renamed pods no longer carry, and it is a pre-existing object that must not be written to. Also create an `audit018-restic` NetworkPolicy in `gameplane-games`, labeled `gameplane.io/audit: "018"`, allowing egress to pods labeled `app.kubernetes.io/name: audit018-restic` in `gameplane-system` on TCP 8000 (same shape as the fixture's `allow-egress-to-restic`, renamed and re-labeled). Teardown deletes the Secret, then the `audit018-restic` NetworkPolicy, then the `audit018-restic` Deployment/Service.
- **Second games namespace (item 14)**: create namespace `audit018-games2` (labeled `gameplane.io/audit: "018"`) with one small `audit018-` GameServer in it, for `servers-filter-by-namespace`. Teardown deletes the GameServer, then the namespace.
- **Network capture override (item 17)**: `capture.enabled=true` is a per-round Helm value override (default `enabled: false` at `charts/gameplane/values.yaml:574`), not a per-object convention. Record the pre-round value and the `helm upgrade --set capture.enabled=true` command used in `rounds.md`, and record the `helm upgrade --set capture.enabled=false` (or equivalent revert) that restores it at teardown, plus a before/after diff of any config this toggle changes.
- **In-cluster OCI registry (items 6, 21)**: stand up `audit018-registry` (an in-cluster OCI registry, e.g. a `registry:2` Deployment + Service in `gameplane-system`, labeled `gameplane.io/audit: "018"`) and an `audit018-` OCI ModuleSource created with `kubectl` (never editing the pre-existing `default`/`uploads` ModuleSources). Push one cosign-signed and one unsigned bundle for the signature-verification rows. Teardown deletes the ModuleSource, then the registry Deployment/Service.
- **CSI snapshot support (item 20)**: k3s local-path has no CSI snapshots (`github.com/kubernetes-csi/external-snapshotter/client/v8`, see `docs/dependencies.md`), so INV-CRD-036/037 install `csi-driver-host-path` plus the external-snapshotter's snapshot controller and CRDs for the round. This is a cluster-wide install, not a per-object one; record the manifests/Helm release used in `rounds.md` and uninstall both (driver and snapshot controller/CRDs) at teardown.
